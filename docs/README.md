# OctoAcme Project Management Docs

This repository contains the project management process documents used by OctoAcme. Use this README as the entry point to understand the lifecycle, roles, and key workflows that guide project delivery.

## Project management processes summary

OctoAcme’s project management approach follows a clear lifecycle that starts with validating a business need and ends with delivery, learning, and continuous improvement. The team begins with project initiation, where stakeholders align on the problem, goals, measurable outcomes, and a high-level timeline. From there, work moves into planning, where scope is broken into backlog items, dependencies are mapped, milestones are defined, and delivery expectations are set through acceptance criteria and the Definition of Done.

During execution and tracking, teams run standups, manage work in a board, monitor progress against milestones, and escalate blockers when they affect delivery. The organization also emphasizes risk and communication as ongoing practices: the team tracks issues in a risk register, reviews them during weekly syncs, and communicates status updates through simple stakeholder-ready templates. As work nears release, the process focuses on validation, deployment readiness, and ensuring that quality checks and service readiness are in place before production release. After delivery, the team closes the loop through retrospectives and follow-up actions that turn lessons learned into clear improvement work.

## How to use these docs

Start with the project management overview to understand the overall lifecycle, then move into the document that matches your current project phase or need. Use the initiation guide when validating a new idea, the planning guide when creating scope and backlog items, and the execution guide when managing day-to-day delivery. Refer to the risk, communication, release, and retrospective documents when monitoring delivery health, preparing for deployment, or capturing learning after launch.

The team also defines core roles and responsibilities in the personas guide so that project work remains clear, accountable, and aligned across product, project, engineering, QA, and stakeholder groups.
